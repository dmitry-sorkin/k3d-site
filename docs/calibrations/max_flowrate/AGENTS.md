# AGENTS — docs/calibrations/max_flowrate/

Maximum volumetric flowrate calibrator: a Go program compiled to WebAssembly,
embedded in the K3D site as an MkDocs Material page. Generates G-code for
printing a strip of retraction-speed samples with increasing volumetric
flow rate.

## Build

Two independent chains. **Touching `main.go` requires both**:

```bash
# 1. Rebuild WASM (after main.go change). Requires Go >= 1.26 (see go.mod).
./build.sh                 # Linux / macOS / WSL
build.bat                  # Windows

# 2. Rebuild the static site (after any docs/ or asset change)
python -m venv .venv && .venv/Scripts/activate
pip install -r .github/workflows/requirements.txt
properdocs build --clean
```

`build.sh`/`build.bat` run `GOOS=js GOARCH=wasm go build -o assets/wasm/k3d_mfr_lib.wasm main.go`.
The resulting ~3.4 MB `assets/wasm/k3d_mfr_lib.wasm` **must be committed** — the
site is static.

## Layout

```
docs/calibrations/max_flowrate/
  index.md            Stub article linking to calibrator.md
  calibrator.md       MkDocs page hosting the live UI (the actual app)
  main.go             Go source → WASM. All calibration logic, validation, G-code emission
  go.mod              Module k3d_rct, go 1.26
  build.sh / build.bat  Cross-platform Go→WASM build
  assets/
    js/
      wasm_exec.js      Vendored Go runtime glue (do not edit)
      gwaloader.js      Loads k3d_mfr_lib.wasm, toggles the Generate button
      lib.js            Form persistence, language strings, profile management
      profileManager.js Save/load/export/import of named profiles
      streamsavermin.js Vendored streaming file-save polyfill (do not edit)
    wasm/
      .htaccess         application/wasm MIME for Apache hosts
      k3d_mfr_lib.wasm  Compiled output of main.go
```

## Data flow

`calibrator.md` (HTML form, IDs `k3d_mfr_*`) ⇄ `lib.js` (localStorage,
validation, lang strings) ⇄ `main.go` via `syscall/js` ⇄
`streamsavermin.js` (browser downloads `.gcode`).

The Go side reads values via `js.Global().Get("document").Call("getElementById", "k3d_mfr_*")`.
Language strings cross the same boundary through
`getLangString(key)` → `window.lang.getString(key)`.

## Invariants

1. **Version constants stay in sync.** `calibratorVersion` in `main.go` and
   `calibrator_version` in `lib.js` (both near the top). Mismatch surfaces
   at runtime as "Please hard refresh". Bump together only when the G-code
   format itself changes.
2. **Form element IDs are the public API across the three layers.**
   `k3d_mfr_*` appears in `calibrator.md` markup, `main.go` `getElementValue`
   calls, and `formFields` array in `lib.js`. Renaming requires all three
   updates.
3. **`assets/wasm/k3d_mfr_lib.wasm` is rebuilt and committed on every
   `main.go` change.**
4. **Generated G-code is append-only** with a
   `;generated by K3D maximum flowrate calibrator …` header. External
   tools may rely on this.
5. **The `log` flag is off in production.** When `true`, every `generate()`
   call dumps ~30 lines of intermediate state to the browser console.

## Conventions

- Russian comments in Go, Russian UI strings, Russian prose in `index.md` /
  `calibrator.md`. English only for identifiers, paths, tool names.
- Form rows in `calibrator.md` are grouped **printer → filament →
  calibration**, with `innerTable`s used for paired X/Y and Start/End
  inputs. Keep this order when adding parameters.
- Adding a parameter = add to `formFields` in `lib.js`, add a row in the
  right group in `calibrator.md`, add entries to both `en` and `ru` cases
  in `initLang`, declare the global in `main.go`, validate the range.
- Tunable defaults live as top-of-file consts in `main.go`:
  `retractSpeed`, `retractLength`, `filamentDiameter`, `sampleSpacing`,
  `relativeExtrusion`, `log`.

## Don't

- Don't edit `wasm_exec.js` or `streamsavermin.js` — vendored.
- Don't bump the two version constants separately.
- Don't add a new language without also teaching Go's `getLangString`
  callers the new keys.
- Don't ship a `main.go` change without rebuilding WASM.
- Don't re-enable `log = true` for production.
- Don't add Go packages beyond `syscall/js` without a clear need.
- Don't reuse the LA- or RCT-specific `storagePrefix` (`k3d_la_profiles`,
  `k3d_rct_profiles`) in `lib.js`'s `ProfileManager` — the MFR calibrator
  must use `k3d_mfr_profiles` and `mfr_calibrator_profiles.json` as
  export filename. Cross-pollination silently breaks profiles.
